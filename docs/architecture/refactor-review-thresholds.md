# 项目再次审查与重构临界值

> 审查日期：2026-07-12  
> 原则：只解决已经发生或可以用运行指标证明的问题，不以文件数量、设计模式数量作为架构质量目标。

## 1. 决定是否重构的临界值

| 观察项 | 达到以下条件才重构 | 未达到时怎么做 |
| --- | --- | --- |
| 正确性与安全 | 会话串写、路由泄漏、权限绕过、旧请求覆盖、资源未释放，出现一次即处理 | 不等待重复发生 |
| 重复代码 | 同一业务规则出现至少 3 处，且修改时必须同步变化 | 1–2 处保持局部实现，可共享类型但不建抽象层 |
| 大文件 | 超过 350 行，同时包含至少 3 个可独立测试/复用的职责 | 单纯模板长或配置数组长不拆分 |
| `any` | 位于 API/框架边界，或已造成字段误用 | 第三方库回调、图表配置等局部 `any` 随业务修改逐步收紧 |
| 注释 | 导出契约、状态事务、回滚、竞态、非直观排序必须说明“为什么” | 不为明显赋值、简单 getter 和模板标签逐行复述语法 |
| 包体 | 首屏 JS > 350 KiB、CSS > 100 KiB；普通异步 chunk > 750 KiB | 指标以内不继续拆 chunk；MapLibre 独立预算 1100 KiB |
| 新基础设施 | 至少 3 个租户共享相同变化点，或已有明确的远程发布需求 | 不引入微前端、动态插件下载、DI 容器或多层 provider |
| 测试 | 涉及会话、路由编译/注册、权限、跨环境客户端时必须测试 | 纯静态 route/meta 和展示样式按风险选择 |

## 2. 本轮已经处理

- 新增租户专属第三方 API 客户端：环境地址、当前租户检查、平台凭据隔离和动态短期请求头。
- 为 Session、HTTP、Compiler、Registry、Runtime、Router 动态注册等关键事务补充代码片段注释。
- 明确静态后台路由与租户 Manifest 路由的目录边界，避免新租户页面重新进入平台 route 文件。
- 新增第三方客户端测试，覆盖错误租户、缺少环境地址和正常动态 header。

## 3. 仍值得做，但应随业务需求进入

### 较高优先级

1. **现有天津/宁波第三方地址硬编码。** 两处业务实现都直接 `axios.create()`，开发和生产地址相同。迁移方案已经写入第三方 API 指南，但应等允许修改对应业务实现时执行，避免本轮越过冻结边界。
2. **固件上传日志和错误类型。** 上传组件仍含较多调试日志及 `any` 回调；下次修改固件流程时，应提取上传状态类型并检查日志是否包含 Token、文件标识或服务端详情。
3. **平台后台树形表单类型。** 菜单、权限的递归 option 构造仍返回 `any[]`。当下一次修改这些页面时，为 TreeOption 建立单一接口即可，不需要先创建通用表单框架。
4. **登录背景图约 1.1 MiB。** 它不在应用主入口同步 JS/CSS 预算内，但会影响登录页弱网体验。只有确定视觉允许 WebP/AVIF 或取得设计源图时再压缩，避免无依据降低画质。

### 指标触发后再做

1. MapLibre 独立 chunk 约 1.0 MiB，目前按需加载且低于 1100 KiB 专项预算。只有地图页真实加载性能不达标时，再评估更换地图能力或延迟加载插件。
2. 多个 400–600 行页面主要位于冻结租户业务和复杂表单。仅当其中出现三个独立职责或重复变更时拆 composable/子组件，不能仅因行数拆文件。
3. 项目仍有较多业务调试 `console.log`，生产构建已经移除 `console.log`。只有需要统一远程诊断、日志等级或脱敏时才引入 Logger；目前不增加日志框架。
4. 第三方 API 目前按租户本地封装。当至少三个租户共享同一协议时再增加共享 adapter，当前不设计 provider 注册系统。

## 4. 明确不建议的重构

- 不把每个函数拆成 service/repository/use-case 三层。
- 不让业务组件直接操作 `router.addRoute()`，也不恢复逐层路由手工卸载。
- 不用动态 import glob 自动发现 Manifest；显式 Registry 更容易评审和排查。
- 不把所有第三方响应强制改成平台 `{ code, data, message }`。
- 不为注释覆盖率而解释每一行语法；注释应固定不变量、失败回滚和设计原因。
- 不修改冻结 `implementation/` 业务逻辑来完成公共框架整洁化。
